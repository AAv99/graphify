## Verdict: DISCARD

The optional `--profile fiscal-law` file-routing feature was **not implemented** (Task 3/4
skipped) because the live collaboration A/B does not support the locator hypothesis:

1. On well-covered topics (HIR) the graph locates files cleanly but does **not beat** plain
   file search — both reach recall 1.00 and 3/3 foundational-start; there is no headroom.
2. On thinly-covered topics (onzakelijke lening) the graph is a **weak** locator that the
   agent must bypass with ordinary file search; its lone metric edge is within noise.
3. The one concrete, real structural gap (missing `herinvesteringsvoornemen` association) is
   **fixable by the bridge/corpus layer** — demonstrated here — but fixing it yields **no**
   measurable collaboration benefit on a saturated case. A CLI profile that only reformats
   locator output would not touch retrieval completeness at all, so it is premature.

The lever that works is retrieval **completeness** (bridge notes in the corpus), not a new
query mode. Building the `--profile` now would add surface area around a null collaboration
result. Recommendation: keep the evaluation harness; do not add the profile; if pursued later,
re-run this exact A/B on tasks where plain file search does **not** already saturate recall.
